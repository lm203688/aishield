# AIShield 定时任务闭环修复方案 v2

## 当前缺口分析

| 缺口 | 现象 | 修复方式 |
|------|------|----------|
| ① 推广技术纳入L3后无人执行 | 每周发现新技术→核对通过→写入周报→无后续 | 每周任务增加"执行已纳入L3的推广技术"步骤 |
| ② MVP需社区反馈但无人发帖 | 跟踪社区数据→但没人去发帖获取数据 | 每周任务增加"社区互动执行"步骤 |
| ③ GitHub Issues发现无人转化 | Issues写入日报→无分析→无功能改进 | 每周任务增加"Issues需求提取"步骤 |
| ④ MVP决策通过后无人启动研发 | 月度决策通过→无研发启动动作 | 月度任务增加"研发计划输出"步骤 |
| ⑤ 产品上新核对通过无人开发 | 原则核对通过→无开发任务分解 | 月度任务增加"产品上新研发任务输出" |
| ⑥ 季度OKR制定后无人跟踪 | OKR写在季报→月度无人检查进度 | 月度任务增加"OKR进度检查"步骤 |
| ⑦ 自动修复后无人验证 | 修复动作执行→第二天无人验证效果 | 每日任务增加"闭环跟踪"章节 |

## 任务一：每日任务（已存在 ID: d5cd6015）

**修改点：新增「闭环跟踪」步骤**

在原有「检查→自动修复→生成日报」流程中，插入第三步：

### 第三步：闭环跟踪（NEW）

**验证昨日自动修复效果**
- 读取昨天日报（daily-YYYYMMDD.md）
- 检查昨天「自动修复」记录的问题
- 验证今天是否已恢复正常
- 未恢复 → 日报标 ⚠️ 并升级

**跟踪需人工介入的问题**
- 扫描最近7天日报，找出所有"需人工介入"标记
- 检查今天状态
- 超过3天未解决 → 标 🔴 并提醒用户优先处理
- 已解决 → 标 ✅ 记录解决方式

### 第四步：生成日报（升级）
- 新增「闭环跟踪」章节
- 存在>3天未解决人工介入问题 → 开头 🔴 提醒

## 任务二：每周任务（已存在 ID: 8e74b2d5）

**修改点：新增三个执行模块**

### 新增 A：L3 推广技术执行（闭环缺口①）

在「自动化推广技术发现」之后增加执行环节：
- 读取上周及历史周报中已纳入L3的推广技术清单
- 对每项已纳入但未执行的技术，执行具体推广动作：
  - 如果是内容营销类：撰写并发布文章/帖子
  - 如果是SEO类：更新网站内容/生成新页面
  - 如果是社区运营类：执行具体互动动作
  - 如果是工具集成类：提交 PR 或注册平台
- 记录执行结果（成功/失败/需人工介入）
- 将执行结果写入周报「L3推广执行」章节

### 新增 B：社区互动执行（闭环缺口②）

在「MVP验证跟踪」之后增加执行环节：
- 检查委托链可视化 MVP 的社区讨论状态
- 如果上周未发帖或帖子已沉：
  - 在 Reddit r/LocalLLaMA 发布/更新讨论帖（标题含 Delegation Chain Security + AIShield）
  - 在 Hacker News 提交 Show HN（如 demo 页面有新功能）
  - 在 GitHub Discussions 创建/回复话题
- 记录帖子链接、互动数据（点赞/评论/阅读）
- 将社区互动结果写入周报「MVP社区验证」章节

### 新增 C：GitHub Issues 需求提取（闭环缺口③）

在「情报源扫描」之后增加分析环节：
- 读取本周所有新 GitHub Issues 和评论
- 提取高频功能需求关键词（如"支持XX平台""增加XX检测"）
- 按出现频次排序，标记 Top 5 需求
- 评估每个需求与当前 ROADMAP 的匹配度
- 将高匹配度需求纳入「产品上新候选池」
- 将分析结果写入周报「用户反馈洞察」章节

## 任务三：月度任务（已存在 ID: 92ff4a0f）

**修改点：新增三个输出模块**

### 新增 A：季度 OKR 进度检查（闭环缺口⑥）

在「L1本体回顾」之后增加：
- 读取本季度 OKR（从季度报告中提取）
- 检查各关键结果的当前完成百分比
- 对比计划进度（如Q1第2个月应完成66%）
- 滞后项标 🔴 并分析原因
- 将 OKR 进度写入月报「OKR跟踪」章节

### 新增 B：MVP 通过后研发计划输出（闭环缺口④）

在「MVP验证决策」之后增加：
- 如果 P0 极致分工通过：
  - 输出具体研发计划：W1-W6 里程碑分解为月度任务
  - 明确下月需完成的里程碑节点
  - 更新 ROADMAP.md 标记 P0 为"研发中"
- 如果 P1 Agent 文化通过：
  - 输出具体研发计划：W1-W10 里程碑分解
  - 明确下月需完成的里程碑节点
  - 更新 ROADMAP.md 标记 P1 为"研发中"
- 将研发计划写入月报「研发启动」章节

### 新增 C：产品上新研发任务输出（闭环缺口⑤）

在「产品上新分析」之后增加：
- 对本月通过原则核对的机会：
  - 输出具体研发任务清单（任务名/负责人/预计工期/依赖项）
  - 明确优先级（P0/P1/P2）
  - 更新 ROADMAP.md 添加新任务
- 对未通过核对的机会：
  - 记录拒绝原因
  - 标记为"归档"，供未来参考
- 将研发任务清单写入月报「产品上新开发计划」章节

## 任务四：新增双周研发进度跟踪（NEW）

**任务名**：AIShield 双周研发进度跟踪
**频率**：每两周周一 03:00（cron: 0 3 1,15 * *）
**目的**：跟踪 ROADMAP 执行，识别阻塞项

执行内容：
1. 读取 ROADMAP.md 和 docs/agent-ecology-evolution-directions.md
2. 检查各研发任务的当前状态：
   - P0 极致分工：委托链可视化引擎、链级编排逻辑、信任收敛算法
   - P1 Agent 文化：文化基线存档、文化漂移检测
   - 产品上新：本月通过核对的开发任务
3. 对比计划里程碑和实际进度
4. 识别阻塞项（缺少资源/技术难点/外部依赖）
5. 检查 GitHub Issues 中标记为 bug 或 enhancement 的问题处理进度
6. 生成研发进度报告（中文），包含：
   - 各任务完成百分比
   - 里程碑达成情况
   - 阻塞项清单及建议解决方案
   - 下两周重点推进项
   - 保存到 c:\Users\xing\Desktop\aishield\eco\reports\biweekly-dev-YYYY-MM-DD.md

## 完整闭环流程图

```
每日任务（L1本体+L3推广）
├── 检查 → 自动修复 → 闭环跟踪（验证昨日+跟踪人工介入）→ 日报
│   └── 异常写入日报 ────────────────────────────────┐
│                                                    ▼
每周任务（L2外部+L3推广）                            每日读取验证
├── 情报扫描 → 竞品分析 → 动态趋势判断
├── 自动化推广技术发现 → 核对 → 纳入L3 ──→ L3推广执行（闭环①）
├── MVP验证跟踪 + 社区互动执行（闭环②）
├── GitHub Issues需求提取（闭环③）────────→ 产品上新候选池
└── 周报
    │
    ▼
月度任务（三层联动+飞轮诊断）
├── L1/L2/L3回顾
├── OKR进度检查（闭环⑥）
├── MVP验证决策 ──→ 通过后输出研发计划（闭环④）
├── 产品上新分析+原则核对 ──→ 通过后输出研发任务（闭环⑤）
└── 月报 + ROADMAP更新
    │
    ▼
双周任务（研发跟踪）◄───────────────────────────────┐
├── 检查ROADMAP各任务进度                           │
├── 识别阻塞项                                      │
└── 研发进度报告 ───────────────────────────────────┘
    │
    ▼
季度任务（战略复盘）
├── 方向复盘（极致分工+Agent文化）
├── Pivot判断
├── OKR制定 ──→ 下季度目标
└── 季报
```
