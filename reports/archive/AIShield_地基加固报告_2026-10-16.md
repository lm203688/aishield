# AIShield 地基加固报告：直击痛点、啃硬骨头

> 视角：不吹楼层、只问承重 ｜ 原则：**避实就虚的漂亮话一句不写，每一个痛点都给文件证据**
> 日期：2026-10-16 ｜ 方法：全仓重扫描 + **实跑测试套件**（隔离 venv，非引用旧结论）
> 实跑结果：`2245 passed / 2 failed / 2 error / 26 skipped`（372s）——**不是全绿**，下面逐条拆

---

## 0. 一句话结论

楼已经盖到了 264 规则、21 条 workflow、11 万行的层次，继续往上盖之前，**有 3 处地基裂纹会在"楼变高"时变成结构事故**：① 依赖地基是**空的**（新环境测试根本跑不起来）；② 状态地基是**沙地**（35 个运行时 JSON 进 git、直接写活文件无原子性）；③ API 地基是**一坨 3236 行的承重墙**（`do_GET()` 一个函数 1002 行）。本报告只做一件事：**把这些裂纹变成可施工、可验收的硬任务**。

## 2. 七大真实痛点（每条附证据 + "楼高了会怎样"）

### 痛点 1：依赖地基是空的——"一条命令跑起来"是假的
证据：
- `requirements.txt` 空、无 `pyproject.toml`；`setup.py` 的 `extras_require` 全是 browser-use/neo4j/kafka 这类集成，**核心的 `cryptography`/`pyyaml` 一个都没声明**。
- `render.yaml` 写着 `pip install -e . 2>/dev/null; true`——**安装失败被刻意吞掉**；Railway 同样只 `pip install -e .`。部署面装不上 `cryptography`，生产就会静默跑 HMAC 降级（见痛点 6）。
- AGENTS.md 的一键启动教人 `pip install pytest cryptography pyyaml`，但**测试套件实际还 import `hypothesis`**（`tests/test_invariant_property.py:34`），按文档装完照样 collection 崩——文档与真实依赖面脱节，新贡献者第一课就是红屏。

楼高了会怎样：每次 CI 事后补救（AGENTS.md 记载 2026-10-05 一天两次同类事故）都是在给这个空地基打补丁。**规则库翻倍、生态翻倍时，"装不全"会指数级放大成"测不全"。**

### 痛点 2：本地 ≠ CI，"测试绿"含三条暗管
证据（本次实跑）：
- **2 failed**：`tests/test_workflow_test_prereq.py` 两例——`.github/actions/prepare-tests/action.yml` 与 `.github/workflows/rule-promoter.yml` 含 CRLF，被自家 E9 门禁拦下。注意：**prepare-tests 正是 E11 强制要求的唯一依赖引导入口**——地基文件自己带着病。
- **2 error**：`e2e_test.py::test`、`quick_test.py::test` 是脚本式遗留文件，被 pytest 当测试收集即报错——纯噪声污染套件。
- **26 skipped**：geo/indexnow/linkages 一整套"服务器未启动"静默跳过；另有 3 个测试因 `security-scan.yml` 已改名 `unified-security-scan.yml` 而**永远 skip**（死测试）。

楼高了会怎样：AGENTS.md 自己定的铁律"跳过即假绿"，现在 26+3 个跳过就是 29 个假绿灯位。楼层越高，越没人敢删跳过——因为分不清哪些是环境skip哪些是真skip。

### 痛点 3：行尾卫生——`.gitattributes` 形同虚设，CRLF 是复发型事故
证据：
- `.gitattributes` 全文只有一行 `merge=union` 声明，**没有任何 `* text=auto eol=lf` 归一化策略**——且它自己都是 CRLF。
- 源码区（排除 `.workbuddy`）**343 个文件含 CRLF**，含 `.github/` 7 个（其中两个直接被 E9 拦）、`.py` 83 个、`AGENTS.md`/`README.md`/`CLAUDE.md` 全中。
- 复发性：E9 是**事后门禁**（提交后才被发现），且本次实测连 `prepare-tests/action.yml` 的 CRLF 都没被 validator 扫出来——**看着有门禁，实际门禁覆盖面有洞**。

实测澄清（不编造）：CRLF 对**检出率无影响**（LF/CRLF 对照实验：prompt 注入各 2 findings、依赖分析各 3、rules.analyze 各 5，完全一致）。所以这是**卫生/CI 事故源**，不是检测缺陷——但正是"不是检测缺陷"才更危险：它不报错，只在你最忙的时候弄坏 CI。

楼高了会怎样：Windows 上贡献/agent 提交 → CRLF → 弄坏 heredoc/门禁 → 守夜误报 → 狼来了多了真警被无视。

### 痛点 4：API 地基是一坨 3236 行的承重墙
证据（AST 实测）：
- `api/server.py`：3236 行，**`do_GET()` 1002 行、`do_POST()` 810 行**——两个函数各近千行，87+ 路由全塞在 if-chain 里。
- 每个路由共享同一套异常命运：81 处 `except Exception` 集中在这一个文件；一个路由的疏忽静默吞掉一场事故的概率 = 1002 行里任何一行出问题全单路由继承。
- `_handle_mcp()` 248 行、`_handle_audit()` 120 行同样是超长函数。

楼高了会怎样：每加一个功能 = 往千行函数里塞 branch；新人无法安全重构（没有 seam 可切）；任何接口级联故障无法定位。**Runtime Guard、信任 API、eBPF sidecar 全部要挂在 API 上——现在没有挂得动的钩子。**

### 痛点 5：状态地基是沙地——35 个运行时 JSON 进 git，写活文件无原子性
证据：
- `git ls-files api/data | wc -l` = **16**（含 `auth_api_keys.json` 772KB、`collab_delegations.json` 2.1MB、`billing.json`、`payments.json`）；`data/state` = **19** 个进 git。**运行时状态与代码历史混在一份真相里**——这正是 AGENTS.md #7 记载的两次并发事故（`data/generated_rules.json` 快照相撞）的同型结构，只是目录换了。
- `_save_json`（`api/server.py:95`）：`with _lock: open(path,"w") + json.dump`——**直接写活文件**，无 tmp+`os.replace`、无 `fsync`。进程在 dump 中途被杀 = 截断的 JSON = 状态永久损坏。
- 锁是**进程内全局单锁**（`api/server.py:80`）：多 worker 部署（Railway/Render 常见）下两个进程同时写同一文件 → 静默丢失更新；且所有状态写串行化，吞吐随路由数线性恶化。
- `data/batch_scans.json` **单文件 24.5MB** 进 git——每次 CI 状态提交都在搬一座山。

楼高了会怎样：agent 注册量、支付流水、协作消息上去之后，"两个并发写者 + 崩溃窗口 + git 真相同步"三者任意组合都会毁状态，而且毁得**静默**（aishield 自己的 audit_chain 却要求别人不可篡改——自己的账本先做到不可丢）。

### 痛点 6：信任地基两处虚签
证据：
- `eco/crypto_sign.py:33`：`import cryptography` 失败即 `_HAVE_CRYPTO=False`，全局静默降级 HMAC——**零告警**。信任层的卖点是"第三方凭公钥离线验签"，降级态实际是"仅服务端自证"，但调用方看到的 `alg` 字段之外没有任何环境级告警。
- `eco/evidence_bundle.py:271`：`hmac_secret=None` 时 `self.hmac_key=None`——即**无秘密的 bundle 可以存在**，"可验证证据包"在缺配置时退化为"无签声明"，需要核对 `verify_bundle_payload` 对无签 bundle 的判定是否 fail-closed。
- `scripts/prove_isolation.py` 全文 **85 行**，原理是 `mock.patch` 把 `subprocess.Popen/run/os.popen` 换成抛异常然后断言零调用——它证明的是"**当前代码路径没有尝试 spawn**"，不是"**不存在能 spawn 的路径**"（例如被扫数据诱导某依赖模块的 import 副作用、C 扩展执行，都不在拦截面内）。

楼高了会怎样：信任层每多接一个第三方消费（badge/凭证/证明流），虚签的后果就从"演示事故"升级为"公信力事故"。而隔离证明是 **AIShield 对竞品最硬的差异化声明**（"绝不执行被扫代码"），用 85 行 mock 撑着，竞品攻击这个点就够了。

### 痛点 7（meta 痛点）：门禁守着门禁，没人守着门禁的覆盖面
证据：
- 项目有 E1–E14 一整套自举门禁，本次实测两个覆盖漏洞：E9 漏扫 `.github/actions/**`（prepare-tests/action.yml 的 CRLF 存在于门禁宣称的防线内却扫不到）；`tests/test_ci_contract.py` 在 `security-scan.yml` 改名后产生 3 个**死测试**——门禁自己被改名事件打穿，无人察觉。
- 异常纪律数字：585 `except Exception` / 48 裸 `except` / ~69 紧接 `pass`；`scanner/sandbox.py`（隔离沙箱！）一个文件 12 处 except。**一个安全工具的代码里，每 200 行就有一个把错误咽回去的地方。**

楼高了会怎样：门禁覆盖面不派生不自愈，每次架构变更（改 workflow 名、挪目录）都会生产一批新的假绿灯。E10–E14 治理的是"失败被吞"，还没有治理的是"**检查从未发生**"。

| # | 硬骨头 | 为什么硬 | 啃下来的判据 |
|---|---|---|---|
| H1 | **统一状态存储层 StateStore** | 35 个 JSON、3 类写入者（server/state_bus/workflow）、git 也有一份；要同时解决原子写、fsync、跨进程锁、schema 版本、损坏自愈、以及"哪些状态该进 git" | `kill -9` 任意时刻 JSON 不坏；单写者进程化或跨进程锁落地；运行时状态 `.gitignore`，git 只存 append-only 账本 |
| H2 | **server.py 拆层** | 1002 行函数没有 seam，87+ 路由拆错一个就是线上事故；要边服务边拆，需要表驱动路由 + 金丝雀对比 | 每个路由 ≤ 40 行；出现 `routes.py` 表 + `services/` + `store/` 三层；无行为变化（路由快照测试钉死） |

| H4 | **信任层 fail-loud 化** | HMAC 降级是"零依赖承诺"与"可验证承诺"的结构性冲突；一刀切禁降级会破坏离线可用性 | 部署/生产入口缺 `cryptography` **启动即失败并明示**；离线单机模式显式标注"local-only 自签"而非默认可公开验证 |
| H5 | **测试信号纯度治理** | 233 处 mock、26+3 跳过、2 个错误文件；要分清哪些 mock 是合理的（网络/时钟）哪些是遮羞布（把真逻辑 mock 掉还断言通过） | 全量跑通 0 unexpected-skip；mock 白名单化并公示；死测试清零；skip 只剩"环境性 skip"且必须显式注明环境变量 |

## 4. 为了楼更高：现在就必须预埋的 6 根结构钢

后面的楼层（Runtime Guard 通电、联邦信任、eBPF sidecar、支付、多 SDK）不是"再写功能"，而是**往现有地基上加荷载**。现在预埋，后期不返工：

1. **S1 依赖钉版 + 装不上即红**：`requirements.txt` 真钉 `cryptography/pyyaml/hypothesis/pytest`（含下限版本）；`render.yaml`/`Dockerfile`/`railway.json` 删掉 `|| true`/`2>/dev/null`；让 E12 从 import 图派生校验的口径覆盖"本地实测可装可跑"。
2. **S2 `.gitattributes` 行尾宪法 + 一次归一化提交**：`* text=auto eol=lf`、`.sh/.yml/.py` 强制 LF；把 343 个 CRLF 文件一次性归一化（动作前先验证 E9 全绿）；CI 前置 pre-commit 钩子，复发即拒。
3. **S3 StateStore + 状态外置**（对应 H1）：一个模块管一切状态写：tmp→fsync→`os.replace`→目录锁；运行时状态全部退出 git；git 里只留 `data/ledger/*.jsonl` 这类 append-only 且 `merge=union` 的账本。
4. **S4 错误语义分型**：`scan()`/API 层把 `error`（校验失败）与 `risk_level`（危险判定）**分成两个字段**——现在打错 URL 也返回 `risk_level:"critical"`（实测确认），消费者无法区分"你输入错了"和"你真危险"。这是 fail-closed 的最后一公里：**fail-loud**。
5. **S5 信任面环境断言**：新增一个 `/api/v1/identity/backend` 自省端点，公开报告"当前后端 = ed25519 / hmac(降级)"；把 `prove_isolation` 三层化（H3），让差异化声明有牙齿。
6. **S6 门禁覆盖面自愈**：E9 扩到 `.github/**` 全量（含 actions 子目录）；`gen_task_registry`/contract 测试改成**从文件系统发现** workflow 而非硬编码名字（改名不再产生死测试）。

| 期 | 周期 | 内容 | 验收（Definition of Done） |

## 6. 验收总标准（这份报告的"完工"定义）

1. 任何人 `git clone` → 按 README 一条命令 → **全绿，0 个意外 skip、0 个 collection error**。
2. 任意时刻 `kill -9` 服务进程，所有状态文件 JSON 结构完好（有测试证明，不是承诺）。
3. 仓库内不再有运行时状态文件；git 里只有代码与不可变账本。
4. `api/server.py` 无超过 80 行的函数；新增路由不需要碰既有路由的代码路径。
5. 缺 `cryptography` 时服务拒绝启动并明示原因；隔离不变量有三层互相独立的证明。
6. `.github/**` 全部 LF、无 CRLF，CI 有钩子挡复发。
7. "跳过即假绿"在本仓库成为不可能：每个 skip 都必须显式绑定环境变量或缺失文件，白名单受门禁派生保护。
