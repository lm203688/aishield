## 0. 执行摘要（给决策者的 9 行）

1. AIShield 当前已不是「扫描器」，而是**带自治飞轮的智能体安全织物雏形**：264 规则、21 条守夜 workflow、三层自动迭代闭环、RSI L5→ASI 威胁建模已落地。
2. 但它仍停在 **「静态 + 单点 + 中心化信任」** 阶段；距离「自治免疫系统」还有 **3 个质变缺口**：无运行时感知、无真正自进化、无集体防御。
3. 下一阶段的核心命题：**把 AIShield 从「人写的规则库」升级为「会自己长规则的、可证明安全的自治安全体」**，同时把信任从「自证」升级为「联邦互证」。
4. 四大范式转移：①静态→运行时免疫；②规则驱动→神经-符号 + 安全自进化；③中心化信任→联邦信任网格；④经验判断→因果 + 形式化证明。
5. 五大领先工程程序（均给出开源融合点）：**NSE 神经-符号引擎 / RSES 安全自进化 / RIL 运行时免疫层 / FTM 联邦信任网格 / FVI 不变量形式化**。
6. 差异化护城河：**「零误报 + 永不执行被扫代码 + 可机器验证」三件套**，目前全球无竞品同时具备；把它形式化证明出来即成为事实标准。
7. 最前沿赌注：**在隔离不变量约束下安全地 embody L5 递归自改进**（Theseus RSI L5），让"自我改进"与"自我豁免"可被区分——这是 2027 年 agent 安全的最终战场。
8. 路线图分三段：2027 H1 打地基（NSE+RIL 通电）→ 2027 H2 自进化（RSES）+ 联邦（FTM）→ 2028–2029 形式化护城河 + 生态标准。
9. 立即第一步（30/60/90 天）：本地 GGUF 语义探针 PoC、Tetragon eBPF sidecar PoC、TLA+ 隔离不变量模型、W3C VC 2.0 信任凭证真签名。

## 2. 范式跃迁：三个根本性转移（专家视角）

### 范式转移 ①：从「静态扫描器」→「运行时免疫织物」
当前所有竞品（Invariant MCP-Scan、Snyk、HiddenLayer、Lakera、Microsoft agent-governance-toolkit）都卡在"扫一次/拦一次"。下一代的胜负在 **runtime**：agent 真正执行工具调用时，是否被观测、被约束、被归因。**静态是必要不充分**——攻击发生在运行时。

### 范式转移 ②：从「规则驱动」→「神经-符号 + 安全自进化」
纯正则（symbolic）零误报但盲区大；纯 LLM（neural）覆盖广但误报不可控。AIShield 的"动作型而非关键词型"铁律是**符号层的王冠**。下一代架构必须是 **neuro-symbolic**：符号层作为"宪法"（可证明、零 FP），语义层作为"探针"（覆盖语义攻击），二者由**可验证的桥接器**连接。并且这个系统要能**在隔离不变量约束下安全地自我进化**——把 L5 递归自改进"安全地 embody 出来"。

### 范式转移 ③：从「中心化信任」→「联邦信任网格」
单点自证（badge）无法形成网络效应。下一代是 **collective defense**：每个节点贡献攻击信号但不泄露原始数据（联邦学习 + 安全聚合），声誉从网格中"涌现"，信任由**透明日志 + W3C VC 2.0 + did:key** 互证。这是 spam/phishing 防御曾经走过的规模化路径，对 agent 经济是**全新绿地**。

> 一句话愿景：**AIShield = 智能体经济的「免疫系统」**——抗体（检测签名）、记忆（威胁知识图谱）、疫苗（预置补丁）、发热（异常检测）、且自身可证明安全。

## 3. 五大领先工程程序（远超市场 + 开源融合 + 具体方案）

### Program A — NSE：神经-符号检测引擎（Neuro-Symbolic Engine）
**痛点**：确定性正则对"语义化 prompt injection / 多步 goal hijack / 混淆代理(slopsquat)"存在盲区；上一轮诊断"语义层默认离线关闭"。
**开源融合（确证）**：
- `llama.cpp` + **GGUF** 量化模型（Q4_K_M，1.5B–3B，如 Qwen2.5-Coder-1.5B / Phi-3.8-mini）：纯 C/C++、零依赖、可离线、CPU/GPU 混合推理（2026-10 实测边端可跑）。[github.com/ggerganov/llama.cpp]
- `onnxruntime-genai`（Microsoft）：跨平台本地推理后端，Windows 原生友好。[github.com/microsoft/onnxruntime-genai]
- `DSPy`（Stanford）：用代码而非字符串定义 prompt 流水线，自动优化语义探针的 prompt/权重，把"语义检测"工程化、可复现。[github.com/stanfordnlp/dspy]

**具体方案**：
1. 语义探针只做**候选生成**，输出必须经**符号层 ratify** 后才升级为结论——**零 FP 铁律不被破坏**。
2. 用 DSPy 的 `BootstrapFewShot` + `MIPROv2` 优化探针，以 AIShield 自有 644 文件 + `scanner/_corpus` 为负样本、**绝不触发自身仓库**为硬约束（沿用 `_is_specific()` 动作型纪律）。
3. 双轨 eval：`LLM-as-judge` 评分 + 对抗基准（`Garak` 风格）度量召回/误报。
**先进性**：全球首个"零依赖离线 + 神经-符号双轨 + 零 FP 保证"的 agent 安全检测器。

### Program B — RSES：安全自进化（Recursive Self-Evolving Safety，即"安全 L5"）
**痛点**：规则晋升半自动、情报链路断点、系统不会反思误报。
**开源融合（确证 + 推断）**：
- `Reflexion`（反思记忆）、`LangGraph`/`smolagents`（可控 agent 编排）做**有界元 agent**：感知情报→假设（起草语义规则）→测试（property-based + fuzzing 留存集）→晋升/淘汰。[推断：用以替代当前半自动 promote_rule]
- `DSPy` 优化探针；`Hypothesis`（property-based testing）做规则回归安全阀。

**具体方案**（关键：**把 L5 安全地关在笼子里**）：
- 元 agent 运行在 AIShield 已有的 `no_execute` + `no_network` 不变量**之外不可写**的沙箱中——它只能"建议规则"，不能改约束自己的机制（精确对应 `docs/rsi-asi-mapping.md` 的 ASI01/ASI10 边界）。
- 闭环：`intel → draft(语义) → test(Hypothesis 留存集) → promote/demote → reflect(FP/FN 记忆)`。每次晋升必须经 `tests/` 回滚安全阀。
- 输出"进化账本"（谁、何时、为何改了哪条规则），可审计、可回滚。
**先进性**：全球首个**被形式化约束的递归自改进安全系统**——把最危险的 L5 威胁，变成自己的核心能力。

### Program C — RIL：运行时免疫层（Runtime Immune Layer）
**痛点**：缺口 A，只扫代码不观测行为。
**开源融合（确证）**：
- `Tetragon` v1.7.0（Cilium / Linux Foundation，2026）：eBPF **无需改 agent** 即可观测进程/文件/网络/exec 事件，已有"AI agent 接 Tetragon"实践（FlowPulse/Canopus）。[cilium.io/blog/2025/05/15/tetragon-ai-agents-canopus]
- `Falco`（CNCF）：运行时异常规则引擎；`AgentSight`：AI agent 诊断的 eBPF 数据方案。
- Linux 6.15/6.16 新增 **eBPF LSM 钩子**，可在安全启动测量路径附加完整性校验。

**具体方案**：
1. 提供 **AIShield eBPF sidecar**：挂在 LangChain/CrewAI/AutoGPT agent 进程上，观测"工具调用真实发生"vs"声明安全"。
2. **连续证明（continuous attestation）流**：把 `schema/trust-attestation-v1.json` 从一次性签发升级为**流式证明**（每 N 秒重签一次运行时状态）。
3. fail-closed 默认策略（上一轮已确认世界级设计）直接作用于运行时拦截。
**先进性**：首个**离线、零依赖、不改 agent 代码**的 agent 运行时安全平面，对抗 Microsoft 免费开源 toolkit 的关键。

### Program D — FTM：联邦信任网格（Federated Trust Mesh）
**痛点**：缺口 C，自证无人消费、网络效应未启动。
**开源融合（确证）**：
- `W3C Verifiable Credentials 2.0`（2025-05 正式标准）：机器可验证、隐私尊重的凭证表达。[w3.org/.../verifiable-credentials-2-0]
- `did:key`（已采用）+ `SPIFFE`（agent 工作负载身份，补全上一轮硬缺口）+ `walt.id`/`SpruceID`（开源 VC 工具箱）。
- 联邦学习 + 安全聚合（参考 `PySyft` / OpenMined）：**各节点上传梯度/信号摘要，不上传原始数据**。

**具体方案**：
1. 把 `aishield-trust/v1` 凭证从"自签占位"升级为 **W3C VC 2.0 + did:key 真签名 + 透明日志（CT 式）**。
2. 建立 **信任联邦协议**：节点间用安全聚合共享"新型攻击特征向量"，全局模型在本地推理——**既 collective defense 又零数据出域**，契合 AIShield 离线基因。
3. 对齐 **Cisco AGNTCY / OASF AI Card** 生态（已在 `docs/agent-mesh-trust-layer.md` 分析）：AIShield 提供"内容信任徽章"叠加在厂商身份之上，做**中立第三方**。
**先进性**：把"信任"从产品功能升级为**协议标准 + 网络效应**，是 2★→10000★ 的唯一正解。

### Program E — FVI：不变量形式化验证（Formal Verification of Invariants）
**痛点**："永不执行被扫代码"目前靠 `prove_isolation.py` 脚本断言，缺乏**机器可检验的证明**；这是可信度的天花板。
**开源融合（确证）**：
- `TLA+`（Lamport）/ `Alloy`（MIT）：对隔离不变量建模 + 模型检查，穷举状态空间证明"扫描器在任意输入（含恶意 scanner）下都不执行被扫代码"。[lamport.azurewebsites.net/tla] [alloytools.org]
- `Hypothesis`（property-based testing）：把不变量写成**运行时属性测试**，每次 CI 真跑、真证。[hypothesis.works]
- `Quint`（Informal Systems）：现代 TLA+ 替代，对分布式/并发不变量更友好。[github.com/informalsystems/quint]

**具体方案**：
1. 用 TLA+/Alloy 写出 `no_execute` + `no_network` + "单一生产者(E13)" 的**形式化模型**，TLC/Alloy Analyzer 穷举证明。
2. 把同一不变量转写为 `Hypothesis` 属性测试，接入 `tests/`，让"证明"成为**每次提交都重跑的 CI 门禁**（而非一次性脚本）。
3. 发布**机器可检验证明产物**作为公开信任锚——竞品只能用博客声称，AIShield 能用证据说话。
**先进性**：全球 agent 安全领域**首个形式化验证的隔离证明**，直接封死"扫描器本身被攻陷"的质疑，是最高级别的科学权威性。

### （补强）Program F — 因果归因 + 合成红队
- **因果归因**：用 `DoWhy`/`causal-learn` 把"看起来恶意"升级为"因 X 因果链而恶意"，降低 FP、提供可解释安全（企业采购的社会许可）。
- **合成红队**：用 `PyRIT`（Microsoft）+ `Garak`（NVIDIA）+ `CyberSecEval`（Meta）+ Microsoft AI Red Teaming Agent 做**agent 对抗 agent** 的持续红队，自动生成对抗样本反哺 NSE 训练集——形成"红队→训练→检测"内循环。

## 6. 护城河与风险

**护城河（远超市场）**
- 三件套唯一性：零误报 + 永不执行被扫代码 + **机器可验证证明**，竞品无法用一篇博客复制。
- 离线联邦：在隐私法规（GDPR/数据出境）收紧下，零数据出域的 collective defense 是合规刚需。
- 安全 L5：把最危险威胁变成核心能力，形成"降维打击"。

**风险与缓解**
- RSES 元 agent 失控 → 用"约束机制本身不可写"的硬隔离（ASI01/ASI10 已建模）。
- eBPF 内核兼容/权限 → 先以用户态 `Falco` 规则 + `strace` 旁路起步，再上 eBPF。
- 联邦冷启动 → 先用 AIShield 自有多节点（CI/scan/deploy）做种子，再开放。
- 形式化门槛高 → 先用 `Hypothesis` 属性测试（低成本）建立信心，再上 TLA+。
