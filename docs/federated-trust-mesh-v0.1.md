# FTM 联邦信任网格 v0.1 — 协议规范（Program D）

> 状态：**协议规范 + 信号 schema 已交付**（`schema/federation-signal-v1.json`）。
> 联邦网络实跑留待种子节点（本仓库自有的 CI / scan / deploy 多环境）——
> 诚实声明：本文件是**协议**，不是"联邦已上线"的战报。

## 1. 解决什么问题（对应蓝图缺口 C）

当前信任是"自证"：AIShield 给自己签的凭证签章，badge 零采纳 ——
单点信任无法对抗 agent 经济的规模化攻击，也没有网络效应。

FTM 把信任从"自证"升级为"互证"：

```
        ┌──────────┐  信号（摘要/特征向量）  ┌──────────┐
        │ 节点 A   │ ◀────────────────────▶ │ 节点 B   │
        │(CI 环境) │   绝不含原始数据        │(扫描服务)│
        └────┬─────┘                        └────┬─────┘
             │            ┌──────────┐           │
             └──────────▶ │ 透明日志  │ ◀─────────┘
              安全聚合     │(CT 式)   │   可审计
                          └──────────┘
```

## 2. 三条铁律（写进 schema 的 invariant）

1. **零原始数据出域**：节点间只传信号（特征向量 / 覆盖缺口 / 误报
   报告 / 晋升通知），不传被扫文件、配置原文、凭证、PII。
   `additionalProperties: false` + 无相关字段 = 结构上不可能泄。
2. **自认证身份**：每个信号用发送节点的 `did:key` 签名 —— 收方从
   DID 直接解出公钥验签，不需要目录服务、不需要信任某个 CA。
3. **可审计**：信号指针可挂透明日志（`evidence_ref`），全局可查
   "谁在什么时候报告过什么"，且日志本身有签名树头防改写。

## 3. 信号类型与语义

| signal_type | 生产者 | 消费者 | 用途 |
|---|---|---|---|
| `novel_attack_feature_vector` | NSE 语义探针（发现正则盲区的新型攻击） | 各节点 NSE | 丰富语义层训练/比对面 |
| `detection_coverage_gap` | 基准测试 / 语料覆盖度门禁 | 规则维护者 | 补规则的情报源 |
| `false_positive_report` | 各节点扫描器（用户申诉坐实后） | RSES reflect | 误报反思的原料 |
| `rule_promotion_notice` | 规则晋升者 | 各节点 | 新规则同步（含 provenance） |

## 4. 安全聚合回合（v0.1 约定）

```
round N:
  1. 各节点本地计算信号 S_i（如某攻击族的特征向量剖面）
  2. 可选差分隐私：S_i += Laplace(0, 1/epsilon_i)，记录 epsilon
  3. 广播签名信号（schema 校验 + did:key 验签 + signal_id 防重放）
  4. 聚合方（轮值节点）计算聚合结果 A = f({S_i})
     —— v0.1 只约定"可联邦平均/中位数"的安全聚合原语，
        不使用需要信任假设的复杂 MPC
  5. 聚合结果 + 参与节点 DID 列表 + 轮次号进透明日志
  6. 各节点本地推理：把 A 作为先验，更新本地检测/规则置信度
     —— **全局模型从不到节点外面去**，只在本地生效
```

轮值节点是**信任弱点**（它能看见所有 S_i）。v0.1 的缓解：轮值 +
日志留痕 + 信号本身已是摘要（无原始数据）。v0.2 再上安全 MPC
（各节点只提交份额，详见 §7 路线图）。

## 5. 声誉涌现（v0.1 最小可用）

- 每个节点的信号历史都在透明日志里 → 可计算：
  - **信号被采纳率**（报告的 gap/FP 后来是否坐实）；
  - **信号被证伪率**（被证伪却不撤回）。
- 声誉 = f(采纳率, 证伪率, 在线时长)。声誉不进入任何门禁的**否决**
  逻辑（防 Sybil 绞杀），只影响信号的**聚合权重**建议值。

## 6. 冷启动（对齐蓝图风险节）

联邦最大的敌人是没节点。冷启动顺序：

1. **种子期（本仓库自有）**：CI / scan / deploy 三个自有环境作为
   首批节点 —— 它们本来就在交换状态，信号化改造成本最低。
2. **邀请期**：已接入的连接器平台（Muse / Grok / NVIDIA）运营方
   邀请制加入，人工审 KYC。
3. **开放期**：协议稳定 + 声誉机制跑通一个季度后，开放注册
   （did:key 即可加入，但初始声誉为中性）。
